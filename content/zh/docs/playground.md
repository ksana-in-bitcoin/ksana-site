[合约 Playground]({{playground}}?lang=zh-CN) 是一个独立的页面，和 [signet 钱包](/docs/wallet/)并列。它跑在[公开 signet](/docs/signet/) 上，每个操作都在你自己的钱包里签名，手续费用测试 KSA 支付。钱包的顶栏、页脚和首页，以及合约详情页，都有它的链接。

## 示例

| 示例 | 展示什么 | Crate |
| --- | --- | --- |
| 计数器 | 最小的合约：一个任何人都能加一的数 | `playground-counter` |
| 资产 | 钱包能列出的内置资产：在上限内增发、销毁、转账 | `mintable-token` |
| KS-20 代币 | 一个 [KS-20](/docs/ks-20/) 代币：转账、带有效期的授权、凭授权额度转出、销毁、在上限内增发 | `token` |
| NFT | 一个 [KS-721](/docs/ks-721/) 合集：铸造、转赠、授权，并按固定价格出售 | `nft` |
| AMM | 两种资产之间的兑换，以及赚取手续费的流动性份额 | `amm` |
| 借贷 | 存款生息、抵押借款、清算 | `lending` |
| 多签钱包 | 由多位所有者共同批准、执行提案的钱包 | `multisig` |
| 锁仓释放 | 随时间逐步释放给受益人的代币 | `vesting` |

每个示例有四个标签页：**应用**，专为它做的页面；**代码**，它的 Rust 源码；**方法**，每个方法一张表单；**记录**，这个浏览器发出的操作。示例之间相互衔接：AMM、借贷和锁仓释放的页面会建议先部署一个资产，资产页面可以直接新建资金池或借贷市场并填好它的资产，也链接到锁仓释放；KS-20 代币页面可以新建一个以这个代币为一边的资金池。[资产与代币](/docs/tokens/)讲了什么时候用哪一种。这些 crate 连同各自的原生测试位于仓库的 `contracts/examples/`；[示例合约](/docs/example-contracts/#playground-examples)把它们和其他示例列在一起。

## 开始

::: steps

### 连接钱包

用 Unisat、OneKey 或 Xverse，账户是比特币 signet 上的 Taproot（`tb1p…`）地址，和 [signet 钱包](/docs/wallet/#connect)一样。Playground 只请钱包签名，从不接触你的私钥。

### 领取测试 KSA

**领取测试 KSA** 向水龙头申请 100 KSA，每个账户每天一次。部署和调用都是路径 B 操作，手续费用 KSA 支付；部署的手续费随模块大小增加。

### 部署一个示例

**部署新合约**会填好示例 `init` 的参数，你也可以改。资产 ID 和合约 ID 长得一样，所以发送之前页面会核对：每个资产 ID 都是一种资产，AMM 的每个 Token 一边都是代币合约；某个 ID 能对应到一种资产时，页面会建议改用它。核对操作，然后在钱包里签名；在区块收录这次部署之前，页面显示的是预测的合约 ID。要用别人部署的合约，打开对方分享的链接，或者用**按 ID 打开**。

### 使用它

**应用**页是示例自己的页面：AMM 的兑换和流动性，借贷的存款、借款和还款，多签钱包的提案。资金池里 KS-20 代币的一边用代币自己的 `transfer_and_call` 付给资金池，所以一笔兑换或一笔存入就是一个操作，不需要授权；KS-20 之前写的代币通过它的 `transfer_from` 扣取，所以 AMM 页会先请你为资金池授权这个数量，页面上有专门的授权按钮。每一次写入都经过同一个核对步骤：先在最新状态上只读地运行一遍，会失败时提前提醒你。

:::

## 写代码，在线构建

**代码**页放着示例的 `src/lib.rs`。编辑器只构建这一个文件，依赖 `ksana-contract-sdk`，和仓库构建这些示例的方式相同。[你的第一个合约](/docs/first-contract/)一步一步地在这里写出你自己的合约。

- **编译**把源码发给编译服务，错误和警告会标在对应的行上。
- **部署这个版本**把你的模块部署成一个新合约，**方法**页的表单跟随你源码里的 ABI 块。修改过的代码可能和示例自己的**应用**页对不上，页面会提示这一点。
- 未经修改的示例源码，编译出的模块和 Playground 自带的那个逐字节相同（哈希记录在 `playground/src/examples/wasm/builds.json`），所以一个示例的部署可以和页面上显示的源码相互核对。
- 没有编译服务的 Playground 副本，依然可以部署自带的模块。按[示例合约](/docs/example-contracts/#build-and-test-them)的说明自己构建模块，再在**代码**页上传 `.wasm`。

### 在线构建的限制

- 一份源码最多 128 KiB，只能作为八个示例 crate 之一来构建，只带这个 crate 自己的依赖。构建时没有网络，120 秒后停止。
- 模块最大 1 MiB，但一个操作最多携带 64 KiB，所以能部署的模块要小于后者。
- 同一个地址每分钟最多构建六次。构建在一个不长的队列里排队，队列满时服务会回答繁忙。

## 用 AI 助手 {#ai}

Playground 的 **AI 助手**页面（[`#/ai`]({{playground}}?lang=zh-CN#/ai)）有一份写给 ChatGPT、Claude、Gemini 等 AI 助手的资料：Ksana 合约怎样运行、[合约 SDK](/docs/contract-sdk/) 的每个函数、gas、各项限制、代币标准、ABI 块和完整的合约，汇成一个 Markdown 文件，由仓库的测试对照代码核对。可以复制、下载，也可以在 [{{origin}}/llms-contracts.txt]({{origin}}/llms-contracts.txt) 以文本打开；请助手写合约之前，先把它交给助手。页面上还有可以先用的提示词。

在示例的**代码**页，**复制给 AI 助手**会把这份资料连同编辑器里的源码、它所在的页面和构建它的 crate、编译器对这份源码的输出一起复制，最后写明助手要做什么：修正错误，或者你接着提的要求。**只复制代码和错误**不带这份资料，用在已经有它的对话里。复制的内容是英文，助手照着英文做得最准；从中文页面复制时，它会请助手用中文回答。

助手的回答是一份完整的 `src/lib.rs`，并说明在哪个页面构建：只用基础 SDK 的合约在计数器页，用到代币标准的合约在“KS-20 代币”、“NFT”或“AMM”页。把它粘贴到那个页面的**代码**页，部署之前先编译。

## ABI 块

合约在自己的文档里向 Playground 说明它的方法：`src/lib.rs` 开头的 `//!` 注释里，一个标记为 `abi` 的代码块，每行一个声明，可以用 `//` 附一句说明。计数器的 ABI 块：

````rust
//! ```abi
//! init()                          // starts the count at 0
//! call increment() -> u64         // adds one; returns the new count
//! call add(amount: u64) -> u64    // adds 1 to 1000 at a time; returns the new count
//! view get() -> u64               // the count
//! event changed(by: Account, value: u64)
//! ```
````

- `init` 在部署时运行一次；`call` 声明会改变状态的方法，作为操作发送；`view` 声明只读的方法，不用签名就能运行。`init` 或 `call` 前面加 `payable`，表示这个方法接收附带的资产。
- `struct` 和 `enum` 声明方法用到的类型，`event` 声明合约发出的事件。
- 类型：整数 `u8` 到 `u128`、`i8` 到 `i128`，`bool`、`String`、`Bytes`、`[u8; N]`，`Account`、`ContractId`、`AssetId`、`Hash`、`TokenId`（各 32 字节），`Option<T>`、`Vec<T>`、元组、`()`，以及块里声明的结构体和枚举；但 `Option` 不能直接套在 `Option` 里，因为它的 `Some(None)` 会被读成 `None`。参数和返回值都用 Borsh 编码，和所有 Ksana 合约一样（[合约](/docs/contracts/)）。

这个块同时也是写给人看的文档：rustdoc 会把它显示成一个代码块。没有 ABI 块的源码照样可以编译和部署，只是没有表单。

## 打开一个合约

[钱包的区块浏览器](/docs/wallet/#history-and-the-explorer)里，合约详情页有**在 Playground 中打开**。示例的部署会在那个示例的页面上打开；其他合约，贴上它的源码或者只贴 ABI 块，就有了表单。Playground 首页的**任意合约**也能按合约 ID 打开。

## 要知道的事

- Playground 只跑在 signet 上。signet 的 KSA 没有价值，这些示例用来学习，不是经过审计的软件。
- 失败的操作照样支付手续费，也照样用掉它的 nonce。
- 页面按链记住你部署或打开过的合约，以及它发出的操作，并以创世区块来区分每条链：网络从创世区块重新开始之后，之前的合约一个也不会列出。
- 每次写入在发送之前都先记录在这个浏览器里。回答丢失的操作会一直占着它的 nonce，直到节点显示它；**释放这个 nonce** 只解除这条本地占用，什么也不会取消，因为别的节点仍可能收录那笔旧操作。清除网站数据会失去这层保护。
